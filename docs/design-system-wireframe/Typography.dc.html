Design System Wireframe Typography · DS-37 · draft · revision 2

Typography

The type scale as Tailwind utility classes, with no components. Eleven composed classes, heading-2xl … heading-xs and body-lg … body-2xs, are each built from existing theme utilities with @apply. Weight, family, tone, truncate and line clamp are stock utilities you add to the same element. The class sets the look; you choose the element. Every sample on this canvas is rendered by the class string shown next to it.

01

One composed class per element gives the full style. Modifiers change one property at a time. The chip on the right is the element the author wrote: the class never changes it.

07

Modifiers · cascade contract

All typography classes are single-class utilities in @layer utilities. Tailwind v4 orders utilities by variant, then by each one's first property, then puts utilities with more properties first. Composed classes start at font-family, so every one-property modifier comes after them and wins, whatever the order in the markup. truncate and line-clamp-* come earlier but share no property with the composed classes.

The shorthand resets text-wrap-mode to wrap. Because it is emitted after truncate, the heading wraps again and is clipped. The same happens with text-pretty or text-wrap next to truncate.
08

Truncate · Line clamp

Text wraps by default. truncate keeps one line and ends it with an ellipsis. line-clamp-{n} keeps n lines and ends the last one with an ellipsis. Both work with every heading and body style; use one or the other. The dashed frame is the container (280 px). The full string stays in the DOM, so it is copied, found and read in full by screen readers.

09

States · Focus

Typography is static. There is no hover, pressed, selected, disabled or invalid state, and nothing is in the tab order. A heading shows focus only when it is the target of a skip link or of focus management (tabIndex={-1}), and then only if focus-visible:focus-ring is on it. Interactive children such as links own their hover and focus styles.

Do · dialogs and reusable partslevel comes from the caller

A dialog title is an h2 (Radix Dialog.Title), and the dialog's sections start at h3. A reusable card or section takes the level as a prop instead of hardcoding it, because it may sit under an h1 on one page and an h2 on another. The class stays fixed.

<ProductCard headingLevel={3} /> const H = `h${headingLevel}`; → <H className="heading-md"> <Dialog.Title className="heading-md"> // stays h2

One h1 per page: the page title. A visually hidden h1 (sr-only) is fine when the design shows no visible title.
