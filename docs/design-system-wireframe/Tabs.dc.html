Design System Wireframe Tabs · DS-21 · draft

Tabs

Tabs is a mechanism, not a new look. It switches which panel is shown (Radix Tabs: tablist, tab, tabpanel). The tab list wears the existing switcher looks: segmented (the SegmentedControl strip with its sliding indicator) or tile (the TileGroup icon + label tiles). There is no underline or ink-bar style. Under the list sits the active panel, 24 px below at md.

01

Same look, different job

SegmentedControl and TileGroup pick a value (a form field, role radio). Tabs pick which content is visible (navigation inside a view, role tab). They share CSS and tokens, never the primitive. Rule of thumb: if the choice is saved or submitted, it is a SegmentedControl or TileGroup. If it only changes what is on screen below, it is Tabs.

02

Anatomy · list, gap, panel

The root is a vertical stack: tab list, then the active panel. The list hugs its triggers and starts at the inline start. The panel has no border, fill or padding of its own. It is the consumer's content area and is shown here inside a dashed annotation frame. Dashed lines and gray bars are canvas annotations only.

A disabled tab cannot be the active one. With no value, the first enabled tab is active. A controlled value that points at a disabled or missing tab is a dev-mode console.error.

Disabled listnot supported

Radix Tabs has no group disabled, and a list where nothing can be reached hides navigation. Disable single tabs, or don't render Tabs.

06

Panel

The tabpanel is a focus stop (Radix sets tabindex 0), so keyboard users can reach a panel that has no focusable content and screen readers announce it. It shows only a focus ring, only on keyboard focus. Inactive panels are unmounted by default. With keepMounted they stay in the DOM with hidden, so local state such as half-filled inputs survives a tab switch.

07

Activation mode

Radix activationMode. automatic (default): moving focus with arrows, Home or End also activates, and the panel follows focus. manual: arrows only move focus, and Enter or Space activates. Use manual when showing a panel is slow or has side effects, such as a network fetch, a heavy chart or a route change. Use it also on long tile rows, where arrowing across would load every panel on the way.

08

Overflow · horizontal scroll

This is the ChoiceGroup behaviour, reused as is. The tab list is the scroll container. It never wraps and has no scroll-snap. A 24 px edge fade shows only on the side with hidden tabs. The active tab is scrolled into view on mount and on change, and any trigger that gets focus is too, which covers manual mode. The panel never scrolls with the list. The dashed frame is a 360 px container.

10

Not in v1

Underline / ink barrejected

No new trigger style. Tabs reuse the switcher looks. The underline mock under Navigation in Components.dc.html predates this spec and is superseded (see spec, Notes).

Vertical tabslater

Neither switcher look has a vertical form. Vertical tabs would need a new layout (and ↑ ↓ keys), so they get their own design task if needed.

Closable, draggable, overflow menuout of scope

No close buttons, reordering, badges, or a "More" menu. Long lists scroll. Prev/next scroll buttons follow the same decision as ChoiceGroup.
