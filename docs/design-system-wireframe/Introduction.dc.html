Introduction

The Storybook landing page (src/Introduction.stories.tsx), redesigned around why use it, start from it and customize it. Six bands: hero with the theme switcher tip, Why use it, a live theme showcase, Start from it, Customize in minutes, and a component list that covers every family exported from src/index.ts. Built from shipped components (Button, Tag, SegmentedControl, Breadcrumb, TextField, Switch, Alert) and Tailwind utilities only. Each artboard sets data-theme on its root; the role values come from tokens.css and themes/bold.css in the token block. Copy, links and story ids: docs/specs/Introduction.md.

01

The whole page · desktop · four themes

Same markup in all four artboards; only data-theme on the page root differs (in Storybook the toolbar puts it on <html>). The showcase panel opens on bold in every theme: it sits in a data-theme="default" reset and then its own data-theme, so it always shows exactly the picked theme. Content width 1280 max, 48 px gutters, 96 px band padding.

Why use it

Four things you would otherwise build yourself, each with its proof one click away.

  • Radix UI

    Accessible by default

    Every interactive part is a Radix primitive, so focus, keyboard and ARIA come from Radix, not from hand-written handlers. Names a screen reader needs, like a Dialog title or an IconButton label, are required props.

    Try the Dialog keyboard story

  • Role tokens

    Themed through roles

    Components read only the 87 semantic roles, never raw values. All library CSS sits in @layer ds, so one [data-theme] block of yours restyles everything, in any import order.

    Read the theming contract

  • createTheme() · checkContrast()

    Generate and verify a theme

    createTheme() turns one brand color, fonts, radius and shadow into a complete theme block. checkContrast() checks every text and UI pair against WCAG AA, so a failing theme never ships.

    Read the theming guide on GitHub

  • Stories · jest-axe · coverage

    Tested like a product

    A story per state, keyboard stories for every interactive component, userEvent and jest-axe in every test file. CI runs lint, typecheck and the suite with an 80 % coverage floor on every pull request.

    See the CI workflow on GitHub

02

Phone width · 375 px

Below 768 px: 24 px gutters, 64 px band padding, every grid becomes one column. Headings step down one level of the scale (h1 uses the h2 size, section h2 the h3 size, card h3 the h4 size), because the bold display face in uppercase 800 does not fit a 327 px column at h1 size. Hero buttons stack at full width. The SegmentedControl strip scrolls sideways when the four options do not fit (its built-in behavior), and the code sample scrolls inside its focusable box. Each crop is 820 px tall; the themes are spread so every one appears at phone width.

04

Theme showcase · each selection

Picking a segment swaps only the panel's data-theme; the caption shows the value. The panel sits in a data-theme="default" reset first, because dark only sets color roles: without the reset a dark panel on a bold page would inherit bold's fonts, radius and 48 px controls. Third artboard proves it: a bold-dark page with the dark panel is square, flat and in Red Hat. The selection is local state; it does not change the page or the toolbar.
