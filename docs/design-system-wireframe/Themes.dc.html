Design System Wireframe Themes · DS-2 · draft

Themes

Four themes on the DS-26 contract. default is today's Wireframe, unchanged. dark is its dark mode (DS-27 colors kept, photos dimmed). bold and bold-dark prove a consumer can change the whole look: an ultramarine brand, lavender and indigo neutrals, Bricolage Grotesque / Figtree / IBM Plex Mono, uppercase heavy headings with sentence-case labels, round corners, hard offset shadows, 2 px lines and 48 px controls. Every panel renders the same markup and the same component CSS; only the data-theme attribute on the panel root differs, and the role values come from src/styles/tokens.css and src/themes/bold.css (copied into the token block of this board).

01

Four themes, one component set

Heading + body, Button (primary, secondary with focus-visible, ghost), TextField (default, invalid), Checkbox (checked, focus-visible), Tag (solid, subtle, outline) + Badge, Alert (success, error), Slider (thumb focus-visible with value bubble), Dialog on its overlay. Identical markup in all four artboards.

05

Type scale · Wireframe vs bold

default and dark share the Wireframe scale; bold and bold-dark share the bold scale. bold flips Wireframe's case logic: headings are uppercase, heavy (800) and slightly tight; labels drop uppercase and wide tracking for bold sentence case. Body grows to 17 px, buttons to 16 px bold, controls to 48 px.

08

createTheme() input

The ThemeConfig for each theme (src/theme/createTheme.ts). createTheme() owns color generation, fonts, radius and shadow; it always emits the default weights, type scale and shape, and caps neutral tint chroma at 0.03. The designed values above are normative: DS-12 appends the roles the generator cannot express (listed under each input) as a second block with the same selector, then runs checkContrast() on the merged values.

darkshipped in tokens.css
createTheme({
  name: 'dark',
  brand: '#000000',
  fonts: {
    heading: "'Red Hat Mono', ui-monospace, monospace",
    body: "'Red Hat Text', system-ui, sans-serif",
    label: "'Red Hat Mono', ui-monospace, monospace",
  },
  radius: {},
  shadow: {},
  mode: 'dark',
})

Generator output equals the DS-27 block except primary, primary-hover, primary-contrast and focus, which come out a step lighter or darker (primary EBEBEB, primary-hover D7D7D7, primary-contrast 292929, focus EBEBEB). The shipped block keeps gray-50, gray-200, gray-900 and gray-50 for those four and adds photo-filter … brightness(0.85).

bold-darkmode dark
createTheme({
  name: 'bold-dark',
  brand: '#4318D1',
  neutral: '#140E3D',
  fonts: { /* same as bold */ },
  radius: { sm: '8px', md: '14px', lg: '24px', full: '9999px' },
  shadow: {
    sm: '0 2px 0 rgb(0 0 0 / 0.6)',
    md: '0 4px 0 rgb(0 0 0 / 0.6)',
    lg: '8px 8px 0 #4318d1',
  },
  mode: 'dark',
})

A separate call, not mode 'both': the 'both' dark block carries colors only, so data-theme="bold-dark" on its own would fall back to Wireframe fonts, type and shape. Appended block: 24 color roles, then the same non-color roles as bold except photo-filter brightness(0.9).
