## Notes

- Component name `Button` (not the literal title): DS-33 and DS-34 both reference `docs/specs/Button.md`, so the spec and canvas are `docs/specs/Button.md` and `docs/design-system-wireframe/Button.dc.html`.
- No token requests. IconButton 18 px icon size and spinner timings (800 ms / 1600 ms reduced-motion) stay component constants; DS-46 will propose `--ds-icon-size-*`.
- Loading = busy, not disabled: `aria-busy` + `aria-disabled`, no native `disabled`, stays focusable, `onClick` → `preventDefault()`, spinner overlay centred, content hidden in flow (width fixed). `disabled` wins over `loading`.
- IconButton `variant` defaults to `secondary` (today's look). `pressed`/`defaultPressed` → Radix `Toggle`; pressed shows `pressedIcon` plus a 2 px black border on secondary/ghost. Spec adds `defaultPressed` and `onPressedChange` beyond the roadmap's `pressed`.
- ButtonGroup: `div role="group"`, no Radix (Toolbar would add roving focus), `attached` defaults to false (8 px gap); attached uses -1 px overlap with z-index raise on hover/pressed/focus; `disabled` via context.
- DS-33 notes: hover selectors must skip `[data-loading]`; with `asChild` icons and spinner wrap `Slot.Slottable`; spinner colour `--ds-color-primary-contrast` on primary, `--ds-color-ink` otherwise; hide spinner in forced-colors.
- Open questions for review: is the 2 px pressed border on secondary/ghost OK next to the filled heart? ButtonGroup default spaced vs attached? `fullWidth` group deferred.
- Canvas height (11200 px) is the designer's estimate; it couldn't render the canvas.
